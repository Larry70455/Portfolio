Daily dispatch import (Excel macro)

Every morning a dispatch export arrives with a different file name. I wrote a VBA macro that finds it, pulls the routes into the team workbook, turns dispatch times into wave labels, and turns long service names into short van codes. Edit the sample below and press Run import to see the same rules at work. The routes and drivers are made up.

RouteDispatch timeStagingDriverService type
RouteWaveVanStagingDriver

What it showsWave times change daily, so the macro sorts the distinct dispatch times from earliest to latest instead of hardcoding clock times. It reads the size or level number out of the service text, so a new van length still works. It also warns about service types it cannot map instead of guessing.

Excerpt from the VBA 
' Clear ALL previous route data (every input column) before writing today's rows,
' so a shorter file never leaves stale rows behind. Skips V, AF, AG, AK - those are
' formulas (MATCH check + rescue totals) and must never be cleared or they break.
Dim clearRow As Long
clearRow = leadsRow - 2
book2WS.Range("B4:U" & clearRow).ClearContents
book2WS.Range("W4:AE" & clearRow).ClearContents
book2WS.Range("AH4:AJ" & clearRow).ClearContents
book2WS.Range("AL4:AQ" & clearRow).ClearContents

The full macro also opens a file picker, reuses a copy that is already open when the file name has a (1) in it, and shows a confirmation with the detected waves. The button on the sheet is a shape with the macro assigned, so nobody needs the Developer tab.

The real dashboard watches connected controllers. It runs on Cloudflare: the latest reading of each unit sits in KV, and history is stored as files in R2. This is a simulated fleet. Click a unit, switch the range, and filter by status.

What it showsI turn a pile of device logs into something an operator can read in seconds. Units that stopped reporting still show their last known data, so history is useful even when you do not know the dates a system was running.

Real figures from the live system: each unit writes about 10 MB a month at one-minute logging, and a full history pull takes roughly 15 seconds.

This is the page the controller serves over its own WiFi. Pick a status and watch the banner, gauges and totalizers react. Gauges move inside a small range around the live value so they look like a real process, and a disconnected unit shows no signal instead of a made-up number.

One second here counts as ten simulated minutes.

I refactored DFRobot's GP8302 4-20 mA DAC library onto Wire.h so the module shares an I2C bus with other devices. This is the same math as the library's calibrated output: set the DAC codes you measured at 4 mA and 20 mA, then ask for a current.

Excerpt from the library 
uint16_t DFRobot_GP8302::output(float current_mA) {
    // inside the calibrated 4-20 mA span, interpolate between the two measured codes
    if (_calibration && (current_mA >= 4) && (current_mA <= 20)) {
        _digital = _dac_4 + (current_mA - 4) * (_dac_20 - _dac_4) / (20 - 4);
        // round to nearest
    }
    return output_mA(_digital);
}
float DFRobot_GP8302::output_mA(uint16_t dac) {
    Wire.beginTransmission(_twiaddr);
    Wire.write(GP8302_CONFIG_CURRENT_REG);
    Wire.write((_digital << 4) & 0xF0);   // low nibble first
    Wire.write((_digital >> 4) & 0xFF);   // then high byte
    Wire.endTransmission();
}
Built

One firmware codebase builds for three boards. Here is the learning flow in the page. Press buttons on the pretend remote, turn Learn on, save a capture under a name, then replay it. Each capture is reduced to a hash of its bucketed timings, so tiny differences between presses still match, and it works for protocols the library cannot name.

The hash, from main.cpp 
// bucketed hash of raw timings - tolerant of small jitter,
// works for ANY protocol including ones IRremote can't decode by name
code.hash = 0;
for (uint16_t i = 0; i < code.len; i++) {
  code.hash = code.hash * 31 + (code.data[i] / 50);
}
